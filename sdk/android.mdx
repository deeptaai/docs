The Klaritics Android SDK collects analytics from Android apps and sends them to your self-hosted Klaritics instance. Add the Maven repository and dependency, then initialize once from your `Application`.

**Artifact:** `com.deeptaai.klaritics:klaritics-android-sdk:1.0.0`

## Requirements

You need a **Project ID** and a **Server host** from the Klaritics dashboard. Your project ID is on the **Getting Started** page.

## Add the repository

The SDK is published to a public Maven repository. Add it in whichever place your project declares repositories:

<CodeGroup>

```groovy build.gradle
allprojects {
    repositories {
        // ...
        maven { url "https://asia-south1-maven.pkg.dev/org-infra-471907/klaritics-android-sdk" }
    }
}
```

```groovy settings.gradle
dependencyResolutionManagement {
    repositories {
        // ...
        maven { url "https://asia-south1-maven.pkg.dev/org-infra-471907/klaritics-android-sdk" }
    }
}
```

</CodeGroup>

<Note>
  If your project uses `dependencyResolutionManagement` with `RepositoriesMode.FAIL_ON_PROJECT_REPOS`, the repository **must** go in `settings.gradle`.
</Note>

## Add the dependency

```groovy app/build.gradle
dependencies {
    implementation 'com.deeptaai.klaritics:klaritics-android-sdk:1.0.0'
}
```

## Configure your build

<Steps>
  <Step title="Keep Klaritics classes in ProGuard / R8">
    If you use ProGuard or R8, keep the Klaritics classes so events are logged correctly:

    ```proguard proguard-rules.pro
    -keep class com.deeptaai.** { *; }
    -dontwarn com.deeptaai.**
    ```
  </Step>
  <Step title="Disable dexing artifact transformation">
    Add this flag to your app module's `gradle.properties`, at `<project>/<app-module>/gradle.properties`:

    ```properties gradle.properties
    android.enableDexingArtifactTransform = false
    ```
  </Step>
</Steps>

## Initialize the SDK

Call `Klaritics.setup(context, config)` once, from your `Application` class or main entry point, before any other Klaritics call.

<CodeGroup>

```kotlin Kotlin
val config = KlariticsConfig("YOUR_PROJECT_ID", "https://YOUR_SERVER_HOST")
Klaritics.setup(applicationContext, config)
```

```java Java
KlariticsConfig config = new KlariticsConfig("YOUR_PROJECT_ID", "https://YOUR_SERVER_HOST");
Klaritics.setup(getApplicationContext(), config);
```

</CodeGroup>

### `KlariticsConfig`

| Argument | Type | Description |
| --- | --- | --- |
| 1st | `String` | Your `project_id` from the Klaritics dashboard (Getting Started page). |
| 2nd | `String` | Your server host — the URL of your Klaritics instance. |

### Verify initialization

When the SDK initializes successfully, this line appears in Logcat:

```text
Klaritics(v2**) successfully initialized for: PROJECT_ID
```

## API reference

All methods are called on the `Klaritics` object. Attributes are `Map<String, Any?>`.

| Method | Signature | Description |
| --- | --- | --- |
| `setup` | `(context: Context, config: KlariticsConfig)` | Initialize the SDK. Call once, before anything else. |
| `logAppEvent` | `(eventName: String, attributes: Map<String, Any?>? = null)` | Log an analytics event sent to Klaritics. |
| `logAggregateEvent` | `(eventName: String, attributes: Map<String, Any?>? = null)` | Log an event that is counted and batched server-side rather than stored individually. |
| `logClientEvent` | `(eventName: String, attributes: Map<String, Any?>? = null)` | Log an event that stays on the device. |
| `setUserIdentifier` | `(userIdentifier: String)` | Attach your own identifier to the current user. |
| `setUserCustomInfo` | `(userCustomInfo: Map<String, Any?>)` | Set user-level properties. |
| `setSessionCustomInfo` | `(attributes: Map<String, Any?>)` | Set properties scoped to the current session. |
| `trackScreen` | `(screenName: String)` | Record a screen view. |
| `logRedirectionEvent` | `(url: String)` | Record a redirection to a URL. |
| `reportCustomError` | `(key: String, errorInfo: Map<String, String>? = null)` | Report a custom error. |
| `getDeviceId` | `(context: Context): String?` | Return the SDK-generated device identifier. |

### Additional Android methods

These are available on Android. On other platforms built on the native iOS SDK they may be no-ops — see [Kotlin Multiplatform parity notes](/sdk/kmp#platform-parity-notes).

`logMetaEvent` · `resetUserCustomInfo` · `resetSessionCustomInfo` · `setCurrentScreenName` · `setPushRegistrationToken` · `setDynamicConfig` · `flushEventsIfAny` · `optOut`

## Common recipes

### Log events

```kotlin
// Sent to Klaritics
Klaritics.logAppEvent("product_clicked", mapOf(
    "product_id" to "sku-123",
    "category" to "electronics",
))

// Counted and batched server-side
Klaritics.logAggregateEvent("purchase_completed", mapOf("value" to 1299))

// Stays on the device
Klaritics.logClientEvent("soft_back_pressed", mapOf("screen" to "home"))
```

### Identify a user and set properties

```kotlin
Klaritics.setUserIdentifier("user_123")

Klaritics.setUserCustomInfo(mapOf(
    "email" to "user@example.com",
    "plan" to "pro",
))

// Session-scoped properties
Klaritics.setSessionCustomInfo(mapOf("network" to "4G"))

val deviceId = Klaritics.getDeviceId(applicationContext)
```

### Screens, redirections, and errors

```kotlin
Klaritics.trackScreen("home")

Klaritics.logRedirectionEvent("https://example.com/offer")

Klaritics.reportCustomError("payment_failed", mapOf("code" to "E42"))
```

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| No `successfully initialized` line in Logcat | Check the Maven URL, the dependency version, and your project ID and server host values. |
| `klaritics-android-sdk` not found | The repository isn't declared, or your project uses `FAIL_ON_PROJECT_REPOS` and it's in `build.gradle` instead of `settings.gradle`. See [Add the repository](#add-the-repository). |
| Events missing in release builds | The ProGuard / R8 keep rules are missing. See [Configure your build](#configure-your-build). |
